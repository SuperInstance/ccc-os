# CCC-OS Output Directory

Generated artifacts from the orchestrator and manual deck generation.

## Files

| File | Generated By | Purpose |
|------|-------------|---------|
| `task_queue.json` | orchestrator.py | Prioritized list of ACT_NOW items from all monitors |
| `deck-cpu-breakthrough.md` | deck.py | Benchmark finding: AVX-512 vs GPU |
| `deck-bare-metal.md` | deck.py | Architecture decision: LLVM + eBPF strategy |
| `deck-hdc-fleet.md` | deck.py | Research summary: HDC core + fleet publishing |
| `cron.log` | cron | Orchestrator run history |

## Task Queue Format

```json
[
  {
    "source": "discussion5",
    "priority": 1,
    "title": "CPU Breakthrough — 5.5x faster...",
    "created": "2026-05-04T02:35:44Z",
    "action": "Generate deck + notify Casey"
  }
]
```

## Deck Format

All decks are Markdown with a standard structure:
- Title + metadata line (type, generation timestamp)
- Horizontal rule
- Slides numbered 1-N, each with:
  - Title
  - Bullet points
  - Optional quote block

Example:
```markdown
# CPU Beats GPU: The AVX-512 Finding
_Type: benchmark_finding | Generated: 2026-05-04T02:42_

---

## Slide 1: Context

- FM ran head-to-head AVX-512 vs RTX 4050 on constraint checking
```

## Consuming These Files

**Human (Casey):** Read the `.md` files directly. Each is self-contained and ≤5 slides.

**Agent (Oracle1/FM):** Parse `task_queue.json` for queued work. Decks are human-readable summaries that can be cross-posted to PLATO or GitHub Discussions.

**Automation:** A future agent could read `task_queue.json` and auto-generate GitHub issues or PLATO tiles from the queued items.
